# AI Agent 워크플로 개선 계획

## 목표

AI Agent가 문제풀이, 실패 분석, 프롬프트 개선, 재검증을 반복한다.
점수 계산과 최종 선택은 Python이 담당하고, 중요한 단계는 사람이 승인한다.

## 현재 문제

- 모델별 컨텍스트 한도와 응답 형식 차이로 빈 응답·JSON 오류가 발생했다.
- 데이터, 설정, 프롬프트, 실행 명령이 나뉘어 수동 확인이 많았다.
- 기술 실패와 답변 품질 실패가 섞여 개선 원인을 찾기 어려웠다.
- 실행 재개, 비용 제한, 결과 계보 확인이 자동화되지 않았다.

## Agent 역할

- **Orchestrator**: 승인, 실행 상태, 예산, 해시와 산출물을 관리한다.
- **Solver**: 정답을 모른 채 DART HTML에서 답변과 근거를 찾는다.
- **Failure Analyst**: Development 실패만 유형별로 분류한다.
- **Prompt Optimizer**: Development 결과로 후보 프롬프트를 만든다.
- **Workflow Repair**: 컨텍스트 초과, 빈 응답, JSON 오류를 개선한다.
- **Python Evaluator**: 결정론적으로 채점하고 통과 여부와 승자를 정한다.

## 자동화 단계

1. 데이터·HTML 해시·사람 검토·외부 전송 승인을 확인한다.
2. Development 기준 프롬프트를 실행하고 실패를 분류한다.
3. 프롬프트 또는 실행 방식을 한 번에 하나씩 개선한다.
4. Development 게이트를 통과한 후보만 사람에게 승인을 요청한다.
5. Validation 결과만으로 최종 프롬프트를 선택한다.
6. 별도 승인 후 Test를 한 번 실행하고 최종 보고서를 만든다.

## 안전 규칙

- 예상 정답은 Solver에게 보내지 않는다.
- Validation과 Test 결과는 프롬프트 개선에 사용하지 않는다.
- LLM은 점수나 승자를 결정하지 않는다.
- 실제 HTML, API 키, 전체 프롬프트는 실행 로그에 저장하지 않는다.
- 실행별 요청 수, 토큰, 비용, 반복 횟수에 상한을 둔다.
- 기존 실행 폴더는 덮어쓰지 않고 모든 산출물의 계보를 기록한다.

## 구현 순서

1. 승인과 실행 상태를 기록하는 Run Manifest를 만든다.
2. 오류 분류와 제한된 재시도 정책을 추가한다.
3. Agent 상태 머신과 Development 개선 루프를 구현한다.
4. Validation 선택과 Test 단발 실행을 연결한다.
5. 실패·롤백·데이터 누출 방지 회귀 테스트와 문서를 추가한다.
